RAG = Retrieval - Augmented Generation(검색 증강 생성)

범용 AI가 알지 못 하는 회사만의 고유 데이터를 기반으로 움직이는 에이전트
LLM (대형 언어 모델) 같은 경우에는 프라이빗한 데이터를 기본적으로 알리가 없음 

왜 RAG가 필요한가 => LLM의 3가지 한계
1. 학습 컷 오프 : 최신 정보의 부재
- LLM의 지식은 학습이 완료된 시점에 고정 

2. 비공개 데이터
- 공개를 하지 않으니 학습하지는 못하고 추정해서 답변을 알려줌

3. 컨텍스트 윈도우 길이의 제한

RAG의 작동 방식은 크게 데이터를 준비하는 인덱싱 과정과 질문에 답변하는 과정으로 나눔

1. 인덱싱 : 사내 문서들을 나중에 검색하기 좋은 형태 (벡터)로 쪼개어 DB에 미리 저장해 두는 사전 작업
2. 질의 처리 : 실제 사용자의 질문이 들아왔을 때, DB에서 질문과 가장 비슷한 근거를 꺼내어 모델에게 주입하고 답변을 생성하는 실시간 작업

벡터 DB의 핵심 개념
일반 데이터베이스는 단어 일치 기반으로 검색 수행
벡터 데이터베이스는 문자의 의미를 기반으로 검색 수행 
=> 문장을 숫자로 변환한 후 벡터 간의 거리를 계산하여 가장 의미가 가까운 문서 검색
